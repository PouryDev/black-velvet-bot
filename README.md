# black-velvet-bot

ربات Python با FastAPI، python-telegram-bot و SQLite است. یک process و یک replica اجرا کنید؛ کش فعالیت و قفل مچ در همان process هستند.

## رفتار ربات

- `/start` در پیوی برای همه پیام خوش‌آمد می‌فرستد؛ عضوهای گروه راهنمای مرحله‌ای رول ناشناس و بقیه دکمه «درخواست عضویت» را می‌بینند. username برای دیدن این منو لازم نیست؛ هنگام ورود به فرم، داشتن **username عمومی تلگرام** الزامی است. درخواست‌های قبلی با وضعیت انتظار نمایش داده می‌شوند و فرم تکراری ساخته نمی‌شود.
- فرم مرحله‌ای: نام، سن ۱۸ تا ۱۰۰، جنسیت، گرایش، پوزیشن، فانتزی، لیمیت، وضعیت و یک عکس. فانتزی و لیمیت تک‌خطی هستند؛ نام حداکثر ۴۸ و هرکدام از فانتزی و لیمیت حداکثر ۱۶۰ واحد UTF-16. یک عکس Photo لازم است؛ آلبوم، document و ویدئو پذیرفته نمی‌شوند. `/discard` فرم را لغو می‌کند. `/register` فرم نیمه‌کاره را ادامه می‌دهد. پیش‌نمایش دکمه اصلاح دارد.
- کارت بررسی با قالب MEMBER و `USERNAME: @...`، عکس **زیر متن** و دو دکمه دقیقاً «قبول» و «رد» به گروه ادمین‌ها می‌رود. فقط ادمین همان گروه می‌تواند تصمیم بگیرد. username هنگام قبول دوباره از تلگرام بررسی می‌شود.
- **افزودن به گروه دستی است.** قبول فقط پروفایل را ذخیره می‌کند و این پیام را می‌فرستد: «به Black Velvet خوش آمدی 🖤 / درخواستت قبول شد؛ تا دقایقی دیگر توسط ادمین‌ها به گروه اضافه می‌شوی.» رد هیچ پیام خصوصی تولید نمی‌کند. خودکار لینک دعوت یا درخواست عضویت ساخته نمی‌شود.
- `/register` در پیوی برای اعضای فعلی، پروفایل کامل را بدون تأیید ورود ذخیره می‌کند. پروفایل قدیمی و کوتاه گروه برای صف خصوصی کافی نیست.
- `/fuck` در پیوی: انتخاب جنسیت و ۱ تا ۳ پوزیشن موردنظر، صف FIFO با سازگاری دوطرفه. `/رجیستر` و `/فاک` نیز در پیوی پشتیبانی می‌شوند. صف خصوصی با صف عمومی مستقل است.
- دو نفر هویت طرف مقابل و نفر شروع‌کننده را فقط در پیوی دریافت می‌کنند. متن هر نوبت با نام مستعار A/B و شماره نشست در گروه منتشر می‌شود؛ پاسخ بعدی به پیام قبلی همان نشست ریپلای می‌خورد. متن برای طرف مقابل هم در پیوی ارسال می‌شود. متن‌ها فوروارد نمی‌شوند. اگر خود کاربر هویتش را در متن بنویسد، ربات آن را تشخیص یا حذف نمی‌کند.
- `/cancel` صف و انتخاب جست‌وجو را لغو می‌کند؛ `/end` نشست را برای هر دو تمام می‌کند. هر نفر فقط یک نشست دارد. نشست بدون پاسخ بعد از ۴۸ ساعت و صف بعد از ۲۴ ساعت منقضی می‌شود. خروج از گروه یا عدم امکان ارسال پیام، نشست را متوقف می‌کند.
- فرمان‌های عمومی قبلی `/register`، `/fuck`، `/cancel` و `!ping` در گروه اصلی حفظ شده‌اند؛ مسیر خصوصی هیچ‌وقت نتیجه مچ را با هویت کاربران در گروه اعلام نمی‌کند.
- برای گزارش یک پیام در گروه اصلی، روی همان پیام ریپلای کنید و `/report` (یا `/report@BotUsername`) را بفرستید. گزارش با نام گزارش‌دهنده، فرستنده پیام و لینک/دکمه مشاهده پیام به گروه ادمین‌ها می‌رود؛ متن پیام گزارش‌شده کپی نمی‌شود. کاربر در گروه تأیید ثبت می‌گیرد و نیازی به start کردن ربات در پیوی ندارد.
- هر کاربر روزی یک گزارش دارد؛ سهمیه در نیمه‌شب **Asia/Tehran** تازه می‌شود. مبنا تاریخ ارسال دستور در تلگرام است تا تأخیر پردازش، سهمیه روز بعد را مصرف نکند. گزارش بدون ریپلای یا لینک معتبر سهمیه را مصرف نمی‌کند. پیام با هویت ناشناس/از طرف کانال قابل گزارش‌دادن نیست؛ باید از حساب شخصی استفاده شود.
- محدودیت گزارش در SQLite فقط یک رکورد برای هر کاربر/گروه نگه می‌دارد و پس از ری‌استارت باقی می‌ماند. ثبت سهمیه و صف ارسال به ادمین‌ها در یک تراکنش انجام می‌شوند. ارسال ناموفق از همان outbox قبلی قابل retry است و برای تلاش مجدد نیازی به ثبت گزارش تازه یا مصرف دوباره سهمیه نیست.

## فعالیت و اخطار

اعضا با پیام عادی و رویدادهای ورود/خروج ثبت می‌شوند. Bot API فهرست کامل اعضای قدیمی را یکجا نمی‌دهد؛ عضو قدیمی تا وقتی پیام ندهد، به ربات مراجعه نکند یا رویداد عضویتش دریافت نشود، قابل پایش نیست. سابقه پیام قبل از راه‌اندازی هم قابل بازیابی نیست.

متن پیام عادی گروه ذخیره نمی‌شود. آخرین زمان در RAM تغییر می‌کند و با اولین پیام بعد از گذشت ۲۴ ساعت از ذخیره قبلی، دوباره در دیتابیس ذخیره می‌شود؛ اولین مشاهده، تغییر عضویت و شروع دوباره پس از سکوت هفتگی استثناهای لازم هستند. زمان‌بند هر دقیقه بررسی می‌کند: ۷ روز سکوت اخطار اول، ۱۴ روز اخطار دوم، ۲۱ روز بن دائم بدون اخطار سوم. قبل از اقدام، زمان فعالیت و عضویت دوباره بررسی می‌شوند. ادمین‌ها و ربات‌ها مشمول بن خودکار نیستند. اخطار در گروه با منشن ارسال می‌شود.

با برگشت کاربر، شمارش سکوت از نو شروع می‌شود؛ اخطار قبلی فوراً پاک نمی‌شود. پس از هر هفته فعالیت، یک اخطار کم می‌شود. سکوت هفت‌روزه جدید، دوره بازیابی اخطار را قطع می‌کند. معیار بن، ۲۱ روز سکوت پیاپی است، نه جمع اخطارهای دوره‌های جداگانه. پیام پیوی و متن منتشرشده توسط ربات، فعالیت مستقیم عضو در گروه حساب نمی‌شود.

SQLite یک کران محافظ ۲۴ساعته هم نگه می‌دارد؛ پس از crash ممکن است اقدام تا یک روز دیرتر انجام شود تا از بن زودرس به‌خاطر ازدست‌رفتن کش جلوگیری شود. خاموشی عادی آخرین زمان‌های کش را ذخیره می‌کند.

## تنظیمات

شناسه ادمین‌ها در `app/config.py` ثابت است: **`-1004357571815`**؛ به متغیر محیطی احتیاج ندارد. شناسه پیش‌فرض گروه اصلی **`-1004489388121`** است.

توکن داخل image یا کد قرار نمی‌گیرد. از `.env.example` استفاده کنید. `.env` در Git و Docker build context نادیده گرفته می‌شود. تنظیمات قابل تغییر:

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات؛ الزامی |
| `WEBHOOK_SECRET` | رشته تصادفی ۱۶ تا ۲۵۶ کاراکتری، فقط حروف انگلیسی، عدد، `_` و `-`؛ الزامی |
| `WEBHOOK_URL` | آدرس عمومی HTTPS وبهوک؛ مسیر `/webhook` |
| `ALLOWED_GROUP_ID` | گروه اصلی؛ پیش‌فرض مقدار بالا |
| `TELEGRAM_API_BASE` | پیش‌فرض `https://api.telegram.org`؛ در صورت نیاز، آدرس proxy سازگار قبلی را قرار دهید |
| `SESSION_TIMEOUT_HOURS` | پیش‌فرض ۴۸ |
| `QUEUE_TIMEOUT_HOURS` | پیش‌فرض ۲۴ |
| `BOT_BIND_ADDRESS` | آدرس انتشار پورت Docker؛ پیش‌فرض `0.0.0.0` برای دسترسی CDN به سرور. برای پروکسی روی همان میزبان می‌توان `127.0.0.1` تنظیم کرد |

Compose مسیر دیتابیس و پورت داخل کانتینر را روی `/app/data/bot.db` و `8033` تنظیم می‌کند.

برای پایش کامل اعضا و بن، ربات را در گروه اصلی ادمین کنید و مجوز Ban users بدهید. ربات باید بتواند در گروه ادمین‌ها پیام و عکس بفرستد. ثبت وبهوک ادمین‌بودن در هیچ‌کدام از گروه‌ها را بررسی نمی‌کند. پیام خصوصی فقط برای کسانی قابل ارسال است که قبلاً ربات را start کرده‌اند.

## اجرای سرور

پس از انتقال کد جدید به سرور، از پوشه پروژه:

```bash
cp -n .env.example .env
chmod 600 .env
openssl rand -hex 32
nano .env
```

`BOT_TOKEN` و `WEBHOOK_SECRET` را پر کنید؛ خروجی دستور openssl برای secret مناسب است. آدرس وبهوک و در صورت نیاز proxy تلگرام را هم بررسی کنید.

```bash
docker compose build
```

**اگر کانتینر قبلی دیتا دارد، قبل از اولین `up` بخش انتقال زیر را انجام دهید.** برای نصب تازه مستقیماً:

```bash
docker compose up -d
docker compose exec bot python -m app.manage webhook
docker compose logs --tail=100 bot
curl -fsS http://127.0.0.1:8033/health
```

دستور `webhook` بدون بررسی دسترسی ادمین، وبهوک را با secret header و دریافت `chat_member` تنظیم می‌کند؛ آپدیت‌های منتظر تلگرام حذف نمی‌شوند. صرف اجرای کانتینر وبهوک را تغییر نمی‌دهد. بعد از فعال‌شدن secret، وبهوک قبلی بدون هدر معتبر پاسخ 403 می‌گیرد؛ بنابراین این دستور را در همان نوبت راه‌اندازی اجرا کنید.

پورت ۸۰۳۳ به‌صورت پیش‌فرض روی `0.0.0.0` منتشر می‌شود تا CDN یا پروکسی خارجی به آن دسترسی داشته باشد. مسیر تست برنامه `/health` است؛ مسیر `/` صفحه‌ای ندارد. وبهوک فقط درخواست با هدر معتبر `X-Telegram-Bot-Api-Secret-Token` را می‌پذیرد.

## اتصال دامنه و رفع خطای 502

اول از خود سرور تست کنید:

```bash
curl -i --max-time 5 http://127.0.0.1:8033/health
```

اگر پاسخ `200` و `{"ok":true}` است، برنامه داخل Docker و انتشار پورت روی میزبان کار می‌کنند. برای اتصال مستقیم CDN اَروان به ربات، آدرس سرور اصلی (Origin) باید IP عمومی همین سرور، پروتکل ارتباط با Origin برابر `HTTP` و پورت Origin برابر `8033` باشد. مسیر `/webhook` و هدر امنیتی باید حفظ شوند. دسترسی HTTPS کاربران/تلگرام به دامنه در CDN انجام می‌شود.

در نسخه قبلی، پورت با `127.0.0.1:8033:8033` فقط روی localhost منتشر می‌شد؛ در آن وضعیت، دسترسی مستقیم CDN به IP سرور روی ۸۰۳۳ برقرار نمی‌شد. برای اعمال اصلاح پورت، کد/فایل Compose جدید را منتقل کنید. اگر `BOT_BIND_ADDRESS=127.0.0.1` از قبل در `.env` یا محیط shell تنظیم کرده‌اید، آن را برای حالت CDN مستقیم به `0.0.0.0` تغییر دهید. سپس:

```bash
docker compose up -d --force-recreate bot
docker compose ps
```

انتظار می‌رود نگاشت پورت `0.0.0.0:8033->8033/tcp` دیده شود. این تغییر فقط تنظیم Docker است؛ نیازی به build مجدد image نیست و volume `black_velvet_data` حفظ می‌شود. از دستگاهی خارج از سرور هم `http://SERVER_PUBLIC_IP:8033/health` را تست کنید؛ مسیر شبکه و فایروال سرور باید اجازه اتصال به این پورت بدهند. در نهایت:

```bash
curl -i --max-time 10 https://black-velvet.pourydev.ir/health
```

اگر Nginx روی خود سرور نصب کرده‌اید و CDN را به پورت ۸۰ یا ۴۴۳ آن می‌فرستید، می‌توانید `BOT_BIND_ADDRESS=127.0.0.1` تنظیم کنید و upstream آن Nginx را `http://127.0.0.1:8033` بگذارید. در حالت پروکسی داخل Docker نیز upstream باید از شبکه همان کانتینر به ربات دسترسی داشته باشد؛ localhost داخل کانتینر پروکسی به خود همان کانتینر اشاره می‌کند.

## انتقال دیتای کانتینر قبلی

این دستورات برای کانتینر قدیمی با نام `black-velvet-bot` هستند. اول build بالا را تمام کنید تا زمان توقف کوتاه بماند. کانتینر قدیمی را حذف نکنید؛ به‌عنوان نسخه برگشت باقی می‌ماند.

```bash
docker stop black-velvet-bot
mkdir -p migration-data
docker cp black-velvet-bot:/app/data/. ./migration-data/
docker compose run --rm --no-deps -v "$PWD/migration-data:/migration:ro" bot python -c 'from pathlib import Path; import shutil; source=Path("/migration/bot.db"); target=Path("/app/data"); assert source.is_file(), "Source database is missing"; assert not (target / "bot.db").exists(), "Target already has a database; do not overwrite"; [shutil.copy2(p, target / p.name) for p in source.parent.iterdir() if p.is_file()]'
docker compose up -d
docker compose exec bot python -m app.manage webhook
```

کل پوشه بعد از توقف کپی می‌شود تا فایل‌های WAL/SHM احتمالی هم حفظ شوند. دیتابیس مقصد موجود بازنویسی نمی‌شود. migration جدول‌های جدید خودکار و بدون حذف جدول‌ها و پروفایل‌های قدیمی اجرا می‌شود.

## نگهداری

volume نام‌دار **`black_velvet_data`** کل `/app/data` را نگه می‌دارد. با rebuild، restart و `docker compose down` معمولی باقی می‌ماند. برای نگهداری دیتا **`docker compose down -v` یا حذف volume را اجرا نکنید**.

به‌روزرسانی بعدی:

```bash
# کد داخل image کپی شده است؛ restart تنها کد را به‌روز نمی‌کند.
docker compose up -d --build
docker compose exec bot python -m app.manage status
```

بکاپ سازگار با SQLite در حال اجرا؛ برای هر بکاپ نام فایل تازه انتخاب کنید و یک نسخه را خارج از سرور نگه دارید:

```bash
docker compose exec bot python -m app.manage backup /app/data/backup-2026-11-04.db
docker compose cp bot:/app/data/backup-2026-11-04.db ./backup-2026-11-04.db
```

اگر بن به دلیل نداشتن دسترسی انجام نشود، ربات در گروه ادمین‌ها درخواست ادمین‌شدن و مجوز Ban users می‌فرستد؛ این یادآوری برای هر گروه حداکثر روزی یک بار فرستاده می‌شود. خطای بن ثبت می‌شود و عضو بن‌شده علامت نمی‌خورد. اگر ربات در گروه ادمین‌ها هم اجازه ارسال نداشته باشد، خطای ارسال در `status` قابل مشاهده است.

وضعیت صف‌ها و تلاش دوباره برای عملیات ناموفق پس از اصلاح دسترسی/تنظیمات:

```bash
docker compose exec bot python -m app.manage status
docker compose exec bot python -m app.manage retry-failed
```

وبهوک، درخواست‌های حساس را قبل از پاسخ 200 در inbox ثبت می‌کند؛ آپدیت تکراری دوباره پردازش نمی‌شود. ترتیب درخواست‌های هر کاربر هنگام retry حفظ می‌شود. پیام عادی گروه از inbox عبور نمی‌کند تا برای هر پیام write تولید نشود. محتوای inbox و ارسال موفق از outbox پاک می‌شود؛ شناسه‌های جلوگیری از تکرار ۷ روز نگه داشته می‌شوند. فرم‌های رهاشده بعد از ۳۰ روز حذف می‌شوند. پروفایل و درخواست ادمین تا زمان مدیریت دستی داده‌ها باقی می‌مانند.

ارسال‌ها محدودیت سرعت دارند. خطاهای موقت و 429 خودکار retry می‌شوند؛ خطاهای دائمی در `status` قابل مشاهده‌اند. Bot API ارسال exactly-once ندارد: اگر تلگرام پیام را دریافت کند و پاسخ شبکه یا commit محلی از دست برود، retry ممکن است یک نسخه تکراری بسازد. تصمیم ادمین و ساخت نشست در دیتابیس تکراری نمی‌شوند.

## تست توسعه

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

تست‌ها از توکن واقعی و Telegram زنده استفاده نمی‌کنند. نمایش نهایی در کلاینت تلگرام و دسترسی‌های گروه باید پس از استقرار جداگانه بررسی شود.
